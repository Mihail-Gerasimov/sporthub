**Дата:** 2026-09-10
**Инструмент:** Playwright MCP `@playwright/mcp@0.0.53` — впервые в этом проекте
**Стенд:** контейнеры `npm run app:up`, живая мигрированная база

## Зачем этот прогон

Всё, что можно спросить у сервера, уже прогнано библиотекой — девять чек-листов,
316 проверок. Здесь проверялось только то, чего API не покажет: **живой интерфейс**.
Такие шаги во всех прежних отчётах значились как «не прогонялось: интерфейсное».

MCP даёт то, чего библиотека не даёт удобно: дерево доступности страницы вместо
селекторов наугад, состояние после каждого действия и подписи, которые слышит
экранный диктор.

## Найденный дефект

### Подпись ссылки в шапке врала о том, куда ведёт

**Как проявилось.** Дерево доступности показало ссылку с подписью
`aria-label="Перейти в личный кабинет"`, ведущую на `/profile/club/8`.

**Почему это дефект.** «Личный кабинет» в модели фазы 35 — это `/profile/me`,
совсем другой адрес. Ссылка ведёт в кабинет **последнего открытого лица**. Видимая
подпись рядом при этом верна — там имя лица, — а подпись доступности осталась
от времён, когда кабинет был один. Человек с экранным диктором слышал «личный
кабинет», а попадал в клуб.

Это ровно тот класс, который видно только через дерево доступности: на экране всё
выглядит правильно.

**Исправлено:** подпись называет цель — `Перейти в кабинет: <имя лица>`. Тесты,
завязанные на прежний текст, переведены на регулярное выражение.

## Замечание, требующее вашего решения

### API отдаёт карточку скрытой публикации гостю

`GET /api/clubs/8` и `GET /api/clubs/by-slug/...` отвечают **200** и отдают
скрытую модератором публикацию целиком, вместе с расписанием и полем
`status: "hidden"`. Страница при этом показывает «Публикация скрыта», а запись
на слот закрыта (403).

**Дыры нет:** данные витринные — это публикация, которая была публичной, — и никакое
действие с ней невозможно. **Но принцип нарушен:** фаза 34 закрывала ровно такую
схему — «данные уехали в поток ответа, просто не нарисованы».

Чинить не стал: закрытие маршрута задело бы кабинет владельца (он свою скрытую
публикацию видеть должен, иначе не сможет её починить) и админку. Правильная форма —
отдавать скрытую карточку только владельцу и модератору, а гостю отвечать отказом;
это решение о продуктовом поведении.

## Чего проверить не удалось

**Карта Яндекса не грузится в этом окружении:** `net::ERR_BLOCKED_BY_CLIENT.Inspector`
на `api-maps.yandex.ru`. Это блокировка на стороне клиента, **не CSP** — нарушений
политики в консоли нет ни одного, а `connect-src` телеметрию содержит. Маркеры,
popup по клику и пересчёт центра при смене города остаются непроверенными.

**Редактор доп-услуг** (`AdditionalOfferingsEditor`) не проверялся: правка требует
сохранения формы, а форма шлёт полное расписание — на живых данных это лишний риск
при известном контракте (см. долг про `scheduleSlots`).
