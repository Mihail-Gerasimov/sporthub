## Bug #1 — Hidden trainer не исчезает с главной (CRITICAL)

**Что:** После скрытия `trainers[2].status='hidden'` (через admin модерацию) тренер «тест тест» (id=3, slug «тест-тест») продолжает рендериться:

1. `/` → секция «Тренеры под текущие фильтры» (3 в выдаче, должно быть 2)
2. `/` → «Популярные тренеры» (4 карточки, должно быть 3)
3. `/` → «Свободные окна тренеров» (5 окон, одно из них — тест тест)
4. `/` → Также счётчик `4 тренеров в каталоге` не уменьшился до 3

**Где работает корректно:**

- `GET /api/trainers` ✅ — возвращает только id ∈ {1, 2, 4} (без id=3 hidden)
- `GET /api/trainers/3` (detail) — возвращает 200, но клиентский page рендерит `HiddenPublicationNotice` ✅
- `/profile/provider/publications` ✅ — provider видит badge «Скрыто»
- `/service-portal/moderation` ✅ — admin видит status

**Где баг:**

- SSR главной `/` не использует `/api/trainers`, а вызывает `getTrainers()` (или подобную функцию из `lib/db.ts`) **без фильтра по status='published'**.

**Что проверить в коде:**

- Скорее всего `src/app/page.tsx` или `src/components/trainers/PopularTrainers.tsx` / `TrainerAvailability` фетчит `getTrainers()` без `.filter(t => t.status === 'published')`.
- Аналогичное может касаться clubs — на этом прогоне не воспроизвёл (скрывал только тренера).
- Этот баг прямо ломает контракт Phase 22 (модерация скрывает с публики, восстанавливается через 30 дней auto-restore).

**Подтверждение через DOM:**

```
{
  hasTestTest_in_text: true,
  trainerLinksHrefs: ["/trainers/тест-тест", "/trainers/тренер-тренеров", "/trainers/ывавыа-выаываыва", "/trainers/вадим-джонсмитович"]
}
```

## Замечания

1. **Re-direct после login** идёт через UI-клик, `redirect()` в server-action не выполняется автоматически после `POST /api/auth/login` — пользователю нужно кликнуть «Панель управления» в header. Не блокер, но UX можно улучшить.
2. **`browser_navigate`** на `/service-portal/dashboard` после смены пользователя через JS+LS+cookie промежуточно показывает форму логина — нужна перезагрузка.
3. **Все 3 admin-endpoints** (`lift-quarantine`, `bookings/[id]` DELETE, `force-revoke`) принимают тело `{ adminUserId: number }` (а не `{ userId }`) — Zod-strict, расхождение легко поломает скрипты автоматизации.
