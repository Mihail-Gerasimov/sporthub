## Failures

### step-4 (S1) — mark-as-read клик в dropdown

- **Expected:** клик по непрочитанному notification в dropdown помечает его как прочитанное, индикатор исчезает, badge уменьшается на 1.
- **Actual:** клик по тексту уведомления ничего не делает — в `src/components/layout/NotificationBell.tsx:162-181` пункты списка — чистые `<li>` без onClick-handler'а. Индикатор и badge не меняются, API `POST /api/notifications/{id}/read` не вызывается.
- **URL:** `http://localhost:3000/` (при открытом dropdown)
- **Скриншот:** `tests/screenshots/notifications/step-1-4-FAIL-2026-04-23T20-10-00.png`
- **Варианты:** (1) чек-лист устарел, mark-as-read только через полную страницу `/profile/*/notifications`; (2) фича недоделана в `NotificationBell`. Нужно уточнить контракт.

## Blocked

- **S3 step-4** — auto-suppress через `isNotificationTypeEnabled` невозможно end-to-end без check-in: нет slot'ов с endAt в прошлом. Фильтр протестирован косвенно через S4 step-8 (тот же code path).
- **S4 step-5** — auto-expire `pending → cancelled_by_provider` (1h до слота) требует slot'а c `startTime < now + 1h`. В seed все слоты на сегодня 19:30–23:50, сейчас 17:25 — триггер сработает только после 20:50. Полноценная проверка требует либо прямой правки `schedule.json` (грязный тест), либо ожидания ~3ч.

## Issues (побочные находки, не в чек-листе)

### Issue 1 — athlete видит provider-specific чекбоксы в `UserNotificationPreferencesEditor`

**Где:** `src/components/profile/UserNotificationPreferencesEditor.tsx:50-78`.

**Что:** `visibleGroups` фильтруется по `accountType` (правильно скрывает группу `links` у athlete), но `typesByGroup` собирает ВСЕ `NotificationType` без фильтра. В результате athlete внутри группы «Записи» видит 3 лишних чекбокса:
- «Новая запись на ваш слот» (`booking_requested`)
- «Клиент отменил запись» (`booking_cancelled_by_athlete_to_provider`)
- «Запись авто-отменена» (`booking_auto_expired_to_provider`)

Эти типы физически не доходят до athlete (контракт hotfix Phase 26), так что чекбокс бессмыслен.

**Фикс:** внутри `typesByGroup` (или в render-лупе `.map` строки 142) отфильтровать типы по `accountType`, например через новый helper `isNotificationTypeApplicable(type, accountType)`.

### Issue 2 — расхождение `unread-count` vs `/api/notifications`

**Что:** в S4 step-8 после создания `pending` с отключённым `booking_requested` у провайдера:
- `/api/notifications?userId=2&limit=30` — total=4, `booking_requested` нет (фильтрация работает).
- `/api/notifications/unread-count?userId=2` — `unreadCount=5` (было 4, стало 5, delta=+1).

Эндпоинты считают по-разному: один учитывает `notificationPreferences`, другой нет. Возможный фикс — унифицировать фильтрацию в `getUnreadNotificationCount` (в `lib/db.ts`).

### Issue 3 — cookie-race при `browser_navigate` после `document.cookie=...`

Наблюдение инфраструктурное (не баг приложения): повторный `browser_navigate` после установки cookie через evaluate иногда возвращает SSR guest-state. Обход — `window.location.replace()` из evaluate, либо cache-buster в URL, либо повторный evaluate для форс-ре-hydration. Для самих автотестов лучше использовать `page.context.addCookies()` из Playwright напрямую, но текущий MCP такого не предоставляет.

### Issue 4 — Yandex Maps заблокирован

`ERR_BLOCKED_BY_CLIENT.Inspector @ https://api-maps.yandex.ru/v…` на главной — не связано с notifications. Вероятно blocker/adblock в профиле chromium или offline CDN. Карта в проекте на MVP, не критично.
