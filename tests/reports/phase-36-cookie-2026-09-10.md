# Мусорная cookie: замер до и после (этап Э3, шаг 36.26a)

**Дата:** 10.09.2026. **Ветка:** `phase-36`. **Стенд:** контейнеры `npm run app:up`
(`sporthub_web`, `sporthub_api`, `sporthub_postgres`), фронт на `127.0.0.1:3000`,
бэкенд на `127.0.0.1:3001`. Замер — `curl`, три обращения подряд, берётся третье
(первое греет маршрут).

## 1. Что мерили

До шага 36.24 прокси проверял только НАЛИЧИЕ cookie. Любая строка проходила дальше:
Next поднимал маршрут, лейаут звал «кто я» по сети, `SessionGuard` считал sha256
и делал SELECT по таблице сессий, отвечал 401 — и наружу уходил полный HTML-каркас,
в котором уже стоял увод. Гость без cookie получал 307 в один байт.

То есть **строка мусора стоила дороже настоящего входа**, и это была дешёвая точка
нагрузки: чтобы её создать, не нужно ни учётной записи, ни знания пароля.

## 2. Размер и время ответа

| Адрес                       | Без cookie          | `sh-session=x` ДО             | `sh-session=x` ПОСЛЕ    |
| --------------------------- | ------------------- | ----------------------------- | ----------------------- |
| `/profile/me`               | 307, 1 байт, 2.7 мс | 307, **12 524 байта**, 7.7 мс | 307, **1 байт**, 2.5 мс |
| `/profile/me/notifications` | 307, 1 байт, 1.4 мс | 307, **17 238 байт**, 7.3 мс  | 307, **1 байт**, 2.0 мс |
| `/service-portal/dashboard` | 307, 1 байт, 1.4 мс | 307, **18 197 байт**, 12.9 мс | 307, **1 байт**, 1.9 мс |

Строка `never-issued` даёт те же числа, что и `x`: длина мусора на цену не влияла.

**Итог:** мусорная cookie стоит ровно столько же, сколько её отсутствие. Ушло
не только тело ответа, но и сетевое обращение к бэкенду с расчётом sha256
и запросом к таблице сессий на каждый заход.

## 3. Цифра «~77 КБ» в `CLAUDE.md`

📌 **Верная цифра — 12–18 КБ, а не ~77 КБ.** Семьдесят семь — замер dev-режима
с несжатым webpack; в контейнерной сборке тела ответов втрое меньше. Класс проблемы
от этого не меняется, но число в документе неверно. `CLAUDE.md` этой работой не
правится: он в `.gitignore` и его ведёт основная сессия — правка за ней.

## 4. Что проверено сверх размера

| Проверка                                  | Результат                                                                                                           |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Мусорная cookie гасится при уводе         | `set-cookie: sh-session=; Path=/; Expires=Thu, 01 Jan 1970 …; HttpOnly; SameSite=lax`                               |
| Защищённое имя гасится с `Secure`         | `set-cookie: __Host-sh-session=; Path=/; Expires=…; Secure; HttpOnly; SameSite=lax`                                 |
| Страница входа в панель с мусорной cookie | `/service-portal` → **200**, 24 070 байт (человек не заперт снаружи)                                                |
| Годная cookie не гасится                  | `Set-Cookie` в ответе нет вовсе                                                                                     |
| Настоящий вход работает                   | вход → `__Host-sh-session` из 43 символов → `/profile/me` → 307 на `/profile/me/dashboard` → **200**, 121 723 байта |

Гашение обязано совпадать с выдачей по `Path` и `Secure`: браузер сличает cookie
по имени, пути и домену, а `Set-Cookie` с префиксом `__Host-` без `Secure` и `Path=/`
отвергает целиком. Признаки объявлены один раз (`@sporthub/domain/session-cookie`)
и оттуда же берутся выдачей на бэкенде.

## 5. Ограничитель частоты на `/api/auth/me` (шаг 36.26)

Порог — **300 обращений за минуту на СЕССИЮ** (`SPORT_HUB_RATE_LIMIT_AUTH_ME`,
окно — `SPORT_HUB_RATE_LIMIT_AUTH_ME_WINDOW_MS`).

Замер на живом стенде:

| Что делали                                                       | Результат                                                         |
| ---------------------------------------------------------------- | ----------------------------------------------------------------- |
| Стоимость одного «кто я»                                         | 5.6–15 мс                                                         |
| 200 отрисовок кабинета подряд одной сессией                      | все **200** ответили 200, потолка не достали                      |
| Прямой обстрел той же сессии сразу после                         | **429 на 97-м** обращении                                         |
| Отсюда: сколько «кто я» стоит одна отрисовка                     | 300 − 96 = 204 обращения на 200 отрисовок ≈ **одно на отрисовку** |
| Вторая сессия (другой человек, ТОТ ЖЕ адрес) при запертой первой | **200**, кабинет открывается                                      |

⚠️ Последняя строка — главная. Оба клиента приходят с одного адреса: страницы зовут
маршрут из процесса Next, браузерные обращения к `/api/*` идут через переадресацию
Next, а за обратным прокси бэкенд видит один адрес на всю площадку. Потолок «на адрес»
запер бы всех разом — поэтому ключ счёта здесь сессия.

Запас: человеку с десятком вкладок до потолка втрое-впятеро; скрипт упирается
в пять обращений в секунду вместо тысяч.

## 6. Порядок замера

```bash
# ДО — на контейнерах прежней сборки, ПОСЛЕ — после `npm run app:up`
for path in /profile/me /profile/me/notifications /service-portal/dashboard; do
  curl -s -o /dev/null -w '%{http_code} %{size_download} %{time_total}\n' \
    -H 'Cookie: sh-session=x' "http://localhost:3000$path"
done
```

Тестовые сессии, заведённые замером, закрыты выходом; людей и публикаций замер
не заводил.
