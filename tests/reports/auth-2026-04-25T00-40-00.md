## Notes

### LS-ключ

Чек-лист S1 step-5: `localStorage['sh-auth']`. Фактический ключ: **`sporthub-auth-store`** (см. `src/stores/useAuthStore.ts` `AUTH_STORAGE_KEY`). Формат: `{ state: { user: { id, name, email, phone, avatarUrl, city }, accountType, isAuthenticated, isAdmin, isImpersonating, adminOriginalUser }, version: 0 }`. Рекомендую обновить чек-лист.

### Client-side валидация

Modal использует Zod-валидацию на клиенте:

- Email без TLD → «Укажи корректный email»
- Password < 6 символов → «Пароль должен быть не короче 6 символов»
- Пустые поля → кнопка submit disabled

Это срабатывает ДО отправки запроса. Чтобы протестировать серверные ошибки (404/403/409), нужны значения, проходящие client-валидацию.

### Phase 26.7 `db.createUser`

Подтверждено: регистрация через UI добавляет запись в `src/data/users.json` runtime. Test email `test-e2e-1777027102906@local.test` виден в admin-панели Dashboard как user #8, а также проходит повторный login.

### Admin-banner

`ImpersonationBanner` (`src/components/admin/ImpersonationBanner.tsx`) отображается только в режиме impersonation (`useAuthStore.isImpersonating === true`). В чистом admin-режиме Header показывает имя/роль/ссылку «Панель управления» + «Выйти».
