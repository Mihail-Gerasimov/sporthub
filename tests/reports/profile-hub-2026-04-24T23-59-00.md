## Issues

### Issue 1 — UX-inconsistency: schedule и notifications не показывают AccessDeniedCard для guest

**Где:** 
- `src/app/profile/athlete/schedule/page.tsx`
- `src/app/profile/athlete/notifications/page.tsx`
- `src/app/profile/provider/notifications/page.tsx`

**Что:** Для гостя без auth-cookie остальные 14 подмаршрутов показывают `AccessDeniedCard` с badge / heading «Доступ ограничен» / CTA «Войти или зарегистрироваться». Эти 3 маршрута вместо этого рендерят **полноценный UI с пустым контентом** (0 уведомлений или «У вас нет записей»). В `<main>` нет текста «Доступ ограничен» и кнопки login.

**Риск:** 
- Пользовательский риск низкий (API всё равно фильтрует по userId и возвращает пустоту).
- UX-риск средний: guest может видеть pseudo-функционал (пустые tab'ы «Все 0 / Записи 0 / Дисциплина 0») без явной instruktsii «нужно войти».
- Consistency-риск: нарушение contract'а Phase 26 Step 26.1.

**Фикс:** Добавить в server-page этих трёх маршрутов auth-guard через `getAuthUserIdFromCookies()` → если нет или роль не подходит → рендерить `<AccessDeniedCard requiredRole="athlete"|"provider"/>`.

**Скриншот:** `tests/screenshots/profile-hub/step-s5-3-FAIL-guest-notifications-no-denied.png`
