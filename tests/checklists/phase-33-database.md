# E2E: Phase 33 — переезд на PostgreSQL + Prisma

**Role:** cross-role (guest → athlete → provider → admin)
**Base URL:** http://localhost:3000
**Preconditions:**

- PostgreSQL поднят и доступен по `DATABASE_URL` из `apps/api/.env` (порт 5434).
- Миграции применены: `npm run db:migrate --workspace @sporthub/api`.
- Данные перенесены: `npm run db:import --workspace @sporthub/api`.
  ⚠️ **Перед импортом снять копию `data/` и дамп базы** — шаги 24, 30, 41, 44
  меняют данные необратимо, а бэкапов в фазе нет по решению заказчика.
- Собраны общие пакеты и бэкенд: `@sporthub/types`, `@sporthub/domain`, `@sporthub/api`.
- Подняты ОБА процесса: `npm run start --workspace @sporthub/api` (порт 3001) и
  `npm run dev --workspace @sporthub/web` (порт 3000).
  ⚠️ `npm run dev` в корне поднимает только фронт.
- Тестовые учётки берутся из `data/users.json`; вход админа — только через `/service-portal`.
- В расписании есть хотя бы один **будущий** слот со свободными местами и один слот
  с вместимостью 1 — он нужен сценарию гонки. Если таких нет, создать их в step-24.
- Снят эталонный срез `data/*.json` **до** переезда — с ним сверяются шаги 2 и 60.

## Известные ограничения прогона

- Карта на главной под Playwright не грузится: внешний домен карт заблокирован настройкой
  `--allowed-origins` в `.mcp.json`. Ключ подставляется верно — видно в запросе.
  Карту проверять вручную.
- Слоты в рабочих данных могут быть в прошлом. Запись на прошедший слот сразу уходит
  в автоотмену — это верное поведение; для сценариев записи и гонки нужен будущий слот,
  см. Preconditions.
- Сценарий выключенной базы требует прав на остановку контейнера. Если прав нет —
  эмулировать недоступность правкой адреса базы на мёртвый порт с перезапуском только
  бэкенда; тогда step-64 проверяет старт, а не переподключение пула, и это надо отметить
  в отчёте.
- После прогона восстановить базу из дампа, снятого в Preconditions.
