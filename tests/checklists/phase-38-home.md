# E2E: Phase 38 — главная на новом дизайне

**Роли:** гость · человек без лиц · владелец клуба · администратор
**Base URL:** http://localhost:3000
**Предусловия:** база засеяна, фронт и бэкенд подняты (`npm run app:up`), стенд собран
из текущего HEAD — проверять **по содержимому бандла**, а не по времени запуска контейнера.

⚠️ **Шаг не засчитывается по коду ответа.** Проверяется то, что видно на экране
и в дереве доступности. Три фазы подряд дефекты проходили мимо зелёных тестов именно
потому, что проверялся ответ маршрута, а не экран.

⚠️ **Изоляция данных обязательна.** Свой `E2E_RUN_TAG` у каждого прогона:
прогоны ходят в одну живую базу, и общий признак означал бы, что уборка одного
сносит данные другого.

⚠️ **Эталон вида — `phase-38-design-reference.md`.** Сверять не «похоже ли»,
а снятые там числа: размеры, отступы, радиусы, подписи.

## Scenario 1: витрина гостю — ни одной ссылки в никуда

- [ ] **step-1** Открыть `/` гостем. Assert: девять секций на месте, порядок сверху вниз
      совпадает с эталоном
- [ ] **step-2** Assert: герой показывает **четыре счётчика**, и каждое число совпадает
      с ответом `GET /stats/overview`
- [ ] **step-3** Assert: числа в подзаголовке героя совпадают со счётчиками.
      ⚠️ В самом дизайне они разошлись: «52 клуба» против «50+ клубов»
- [ ] **step-4** Собрать **все** внутренние ссылки страницы и каркаса. Assert: для каждой
      `#якорь` на странице существует элемент с таким `id`
- [ ] **step-5** Нажать каждую ссылку навигации шапки. Assert: каждая куда-то приводит,
      ни одна не оставляет экран на месте. «Маркет» и «Командные» → страница
      «раздел в разработке», не 404
- [ ] **step-6** Нажать каждую ссылку подвала. Assert: то же
- [ ] **step-7** Assert: в подвале **нет** признания «ссылки работают как заглушки»
- [ ] **step-8** Assert: на витрине нет обещаний разделов вне фазы — дневников, маркета,
      челленджей, ленты
- [ ] **step-9** Карточка клуба → Assert: открылся **этот** клуб, а не общий список.
      ⚠️ В дизайне все шесть карточек ведут в каталог, имя даже не передаётся
- [ ] **step-10** Карточка тренера → Assert: открылся этот тренер

## Scenario 2: поиск и фильтры

- [ ] **step-11** Ввести запрос в поле героя, нажать «Найти». Assert: **запрос доехал
      до выдачи**, строки отфильтрованы.
      ⚠️ В дизайне поиск теряет введённый текст
- [ ] **step-12** Открыть выпадашку подсказок. Assert: категории пришли из базы,
      а не из списка в компоненте
- [ ] **step-13** Выбрать чип категории. Assert: выдача, карта и «популярное» изменились
      согласованно
- [ ] **step-14** Сменить город. Assert: каталог и карта переехали, выбор пережил
      перезагрузку
- [ ] **step-15** Переключить «Клубы / Тренеры». Assert: сменились выдача, карта и слоты
- [ ] **step-16** Задать запрос, не дающий совпадений. Assert: пустое состояние
      с понятным текстом и способом сбросить
- [ ] **step-17** Assert: выдача пришла **ограниченной** — в запросе есть `limit`,
      и число строк на экране ему равно

## Scenario 7: адаптив

- [ ] **step-38** 1920: Assert: раскладка совпадает с эталоном
- [ ] **step-39** 1440: то же
- [ ] **step-40** 1280: Assert: правая колонка героя ещё на месте
- [ ] **step-41** 1100: Assert: правая колонка героя скрылась
- [ ] **step-41a** **959 и 960** — точка меню с обеих сторон: на 959 горизонтальная
      навигация ушла в меню-кнопку; меню открывается, закрывается по `Escape`, фокус
      возвращается на кнопку; на **960** навигация видна, кнопки меню нет.
      ⚠️ Брейкпоинты у нас `min-width` (mobile-first): точка входит в ШИРОКОЕ состояние.
      Эталон (`max-width:960`) на ровно 960 меню прячет — расхождение на 1px принято
      как отступление (реестр № 24a), не дефект
- [ ] **step-42** **767 и 768** — точка дока с обеих сторон: на 767 сетки перестроились
      и нижняя навигация видна; на **768** док скрыт (`md`, `min-width`).
      ⚠️ Муляжа телефона быть не должно — у нас настоящий адаптив
- [ ] **step-43** 430: Assert: клубы в одну колонку, ничего не уезжает за край
- [ ] **step-44** Assert: ни на одном брейкпоинте нет горизонтальной прокрутки.
      ⚠️ Каждая точка гоняется с обеих сторон — N−1 и N (1919/1920, 1439/1440,
      1279/1280, 1099/1100, 959/960, 767/768, 479/480, 430); то же правило —
      для «семи брейкпоинтов» шага 38.87

## Scenario 10: верификация

- [ ] **step-60** Гостем открыть карточку клуба, у которого верификации нет.
      Assert: знака «проверен» нет, и на его месте не пустая дыра в вёрстке
- [ ] **step-61** Войти администратором, открыть модерацию. Assert: у клуба видно
      состояние «не проверен» и кнопка «Подтвердить»
- [ ] **step-62** Нажать «Подтвердить». Assert: состояние сменилось, в журнале строка
      `verification_grant` с исполнителем
- [ ] **step-63** Выйти, гостем открыть карточку и детальную страницу. Assert: знак
      «Клуб проверен» — с текстовой подписью, не только иконка
- [ ] **step-64** Навести на знак и, отдельно, дать ему фокус с клавиатуры.
      Assert: подсказка открывается в обоих случаях, закрывается по `Escape`
- [ ] **step-65** Войти владельцем, открыть кабинет лица. Assert: письмо «публикация
      проверена» в ящике **этого** лица, имени администратора в письме нет
- [ ] **step-66** Администратором нажать «Отозвать» без причины. Assert: отказ с текстом
      «Причина отзыва обязательна»
- [ ] **step-67** Отозвать с причиной. Assert: знак у гостя исчез; владельцу пришло
      письмо с причиной; в журнале `verification_revoke`
- [ ] **step-68** Скрыть проверенный клуб модератором. Assert: знак снят вместе
      со скрытием. Архивировать другой проверенный клуб владельцем. Assert: знак остался
- [ ] **step-68a** Администратором подтвердить **карточку тренера**. Assert: состояние
      сменилось, в журнале `verification_grant` с предметом-тренером
- [ ] **step-68b** Гостем открыть карточку тренера на главной и `/trainers/[slug]`.
      Assert: знак «Тренер проверен» с текстовой подписью в обоих местах
- [ ] **step-68c** Владельцем карточки открыть кабинет **этого** лица. Assert: уведомление
      о проверке в ящике лица, имени администратора нет
- [ ] **step-68d** Отозвать проверку тренера с причиной. Assert: знак у гостя исчез,
      владельцу пришла причина. ⚠️ Без этих четырёх шагов поле у тренеров уехало бы
      в выкатку без единого экрана при зелёных тестах

## Scenario 11: шрифты и рубль

- [ ] **step-69** На главной русские заголовки. Assert: отрисованы Sofia Sans Extra
      Condensed, а не подстановкой — сравнить ширину строки «НАЙДИ ЗАЛ» с эталоном
- [ ] **step-70** Абзац текста. Assert: Inter, кириллица ровная
- [ ] **step-71** Цена на карточке «от 1 200 ₽». Assert: знак рубля того же веса и
      высоты, что цифры, — не системный
- [ ] **step-72** Замер: три `span` с `₽` — в стеке, в рублёвом шрифте, в `serif`.
      Assert: ширины первых двух равны, третьего нет
- [ ] **step-73** Страница без цен. Assert: рублёвый шрифт **не загружен**
      (`document.fonts`) — браузер не тянет то, чем не рисует
