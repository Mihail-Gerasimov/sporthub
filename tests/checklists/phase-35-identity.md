# E2E: Phase 35 — человек и лица услуг

**Role:** cross-face (гость → человек без лиц → тренер → владелец клуба → оба лица → админ)
**Base URL:** http://localhost:3000
**Прогон:** Playwright MCP по правилам `.claude/skills/e2e-playwright/SKILL.md`.
Отчёт — в `tests/reports/`.

**Preconditions:**

- PostgreSQL поднят, миграции применены, включая колонки адресата уведомлений.
- Данные засеяны сидом фазы 35: по человеку на каждый набор лиц — без лиц,
  с карточкой тренера, с клубом, с обоими, админ.
- Подняты оба процесса: бэкенд `:3001`, фронт `:3000`.
- Браузер стартует без cookie.

⚠️ **Правило прогона (уроки Ф33 и Ф34).** Шаг не засчитывается по коду ответа.
Каждая проверка смотрит в **содержимое**: что вернулось, что видно на экране,
что записано в журнал, осталась ли строка в базе. `200` там, где ожидался отказ, —
это и есть дефект фазы.

⚠️ **Повторяемость (урок 34.68).** Прогон обязан проходить дважды подряд без правок
данных руками. Служебные учётные записи заводит сам прогон, а не регистрация —
у неё свой предел частоты, и на третьем прогоне за час учётки перестанут создаваться.
Посещения для сценариев отзыва прогон создаёт себе сам.

⚠️ **Адреса кабинета (шаг 35.31).** Личный — `/profile/me/*`; кабинет лица —
`/profile/<вид>/<номер>/*`, вид это `club` или `trainer`. Прежние адреса живы:
`/profile/athlete/*` → 308 на `/profile/me/*`, `/profile/provider/*` → 307 на кабинет
первого лица из сессии. У человека с залом и своей карточкой **два кабинета**,
а не один со сдвоенным списком разделов.

📌 **Прогон состоялся 10.09.2026** (шаг 35.44): 36 прошло, 0 упало, 38 не прогонялось
с названной причиной у каждого; найден и закрыт один дефект. Отчёт —
`tests/reports/phase-35-browser-2026-09-10.md`. Обвязка — `tests/e2e-phase-35-harness.mjs`,
прогон — `tests/e2e-phase-35-run.mjs`. Боксы оставлены пустыми: чек-лист перегоняемый.
