# Реестр вырезания надёжности — фаза 38

**Решение заказчика 15.09.2026 (№ 10):** надёжность вырезать целиком — «с кода,
с админки, с профиля». Рейтинг в нынешнем виде никто не понимает; придумывается
заново отдельной работой — долг Д-25. Вырезается **и провайдерская** (бейдж на карточке,
секция на детальной, отсев `excludeDanger`, сортировка `sort=reliability`), **и надёжность
спортсмена** (секция кабинета, фильтр клиентов у лица, бейдж клиента во входящих,
колонка и «Пересчитать» в панели). Подтверждено заказчиком, раздел 14 файла фазы.

**Зачем реестр.** Ни один файл не чистится по памяти. Одна строка — один файл,
у каждого исход. Пропущенная строка — остаток, который следующая фаза честно
перенесёт на новые экраны.

**Исходы, всего четыре:**

| Исход        | Что означает                                                        |
| ------------ | ------------------------------------------------------------------- |
| `СНЯТ`       | файл удаляется целиком                                              |
| `ПРАВИТСЯ`   | из файла уходит надёжность, остальное живёт                         |
| `ПЕРЕЕЗЖАЕТ` | содержимое нужно другому механизму — меняет адрес или имя, не смысл |
| `ОСТАЁТСЯ`   | историческое значение; не трогается, названо здесь, чтобы не искали |

⚠️ **К реестру привязан сторож `apps/api/src/test/reliability-gone.test.ts`**: слово
`reliab` и русское `надёжн` в КОДЕ (без комментариев) обоих приложений и всех пакетов,
вне тестов. Единственное исключение поимённо — токен `reliability_recompute`. Внутри
сторожа список `PENDING` — файлы, чей шаг ещё не пришёл, с номером шага; список
**только убывает**: запись, чей файл уже вычищен, — красная. На закрытии Э3 он пуст.
Диверсии: д-39 (вернуть `ReliabilityBadge` в карточку), д-40 (вернуть `excludeDanger`).

⚠️ **Сторож нашёл три файла сверх разведки** (разведка искала `reliab`, сторож — ещё
и русское слово): `AthleteUpcomingBookingCard.tsx`, `AthleteSchedule.tsx`,
`notification-copy.ts` — тексты «снизит ваш рейтинг надёжности» и «влияет на ваш
рейтинг надёжности». В коде надёжности там нет, но обещание рейтинга, которого больше
нет, — это остаток. Внесены в раздел 3.

### 2.1 ⚠️ Зависимость 38.26 от 38.25

Всё, что снимает 38.26 (Д1, Д2, Д5), сегодня импортирует фронт: `computeAthleteReliability` —
пять компонентов, `ReliabilityResult` — двенадцать, `DISCIPLINE_CONFIG.minCompletedForBadge` —
два, `PROVIDER_RELIABILITY_STATUSES` — тест `booking-scopes.test.ts`. Снять их раньше
фронта — красный `npm run typecheck` у `apps/web`. Поэтому 38.26 закрывается **после**
38.25, и вместе с ним переписываются три теста фронта, чей предмет — домен и типы:
`lib/reliability.test.ts`, `lib/discipline-config.test.ts`, `lib/booking-scopes.test.ts`
(раздел 4.1, строки Т5–Т7).

**Переименование `ATHLETE_RELIABILITY_STATUSES`** (шаг 38.26) — файлы `apps/web/src/lib/booking-scopes.ts`
и `apps/web/src/lib/face-scope.ts`. Новое имя — **`CLIENT_HISTORY_STATUSES`**: набор
`completed` / `no_show` / `cancelled_by_athlete` нужен разделу «Клиенты» лица как история
клиента, без бейджа. Шапка `booking-scopes.ts` переписывается: набор больше не «выведен
из `computeAthleteReliability`», а объявлен как срез истории; тест `booking-scopes.test.ts`
переписывается с поведения функции на само объявление (строка Т7).

## 5. Значение журнала `reliability_recompute` — ОСТАЁТСЯ, и почему это названо

Строки с этим действием живы в базе (пересчёт нажимали в прогонах и руками). Прошлое
не переписывается — правило 37.29. Решение файла фазы (4.5): значение остаётся
в `LOG_ACTIONS` **историческим, с подписью** в `LogsPage`; сторож `reliability-gone`
исключает токен поимённо.

⚠️ **Расхождение с прецедентом 37.29, названо здесь.** Тот шаг для `admin_login`
и `moderation_auto_restore` сделал иначе: значение без писателя **ушло** из `LOG_ACTIONS`
в `LEGACY_ACTION_LABELS` (словарь прошлого в `LogsPage.tsx`), и сторож
`log-action-writers.test.ts` с тех пор краснит любое значение словаря без писателя.
После 38.23 писателя у `reliability_recompute` нет — сторож краснеет. Два выхода:

- **(а) по файлу фазы:** значение остаётся; в `log-action-writers` заводится закрытый
  список исторических значений с причиной. Цена: выпадающий фильтр журнала предлагает
  «Рейтинг пересчитан» — событие, которого система больше не производит; ровно то,
  что 37.29 называл дефектом.
- **(б) по прецеденту 37.29:** значение уходит из `LOG_ACTIONS` в `LEGACY_ACTION_LABELS`,
  `ACTION_TONES` теряет строку, `domain-model.test.ts:373` переписывается. Требует правки
  `LogsPage.tsx` — файла фронта, который на этой волне перекрашивает другой агент.

**На 38.23 делается (а)** — это буква файла фазы, и она не требует чужого файла.
Вопрос (б) вынесен заказчику в отчёте волны: если решит по прецеденту — правка
одной строки словаря и трёх строк `LogsPage.tsx` на шаге 38.25 или 38.26.
