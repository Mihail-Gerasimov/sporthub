# E2E: Maps и Publish-flow (Phase 19 + Phase 23)

**Role:** cross-face (гость + владелец лиц услуг + админ)
**Base URL:** http://localhost:3000
**Preconditions:**

- База поднята и засеяна: `npm run db:up`, затем `npm run db:seed` — в сиде три клуба
  и две карточки тренера с координатами в Самаре
- Ключи карт разведены по процессам: `apps/web/.env.local` держит
  `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` (карта), `apps/api/.env` — `YANDEX_SUGGEST_API_KEY`
  (подсказки) и необязательный `YANDEX_GEOCODER_API_KEY`. В контейнерах те же ключи
  берутся из корневого `.env`
- Подняты оба процесса: бэкенд `npm run start --workspace @sporthub/api`, фронт `npm run dev --workspace @sporthub/web`
- Учётки из `apps/api/src/storage/seed/dev-seed.ts`, пароль — `DEV_PASSWORD`: id=2
  `owner@sporthub.local` (клубы 1 и 2), id=3 `trainer@sporthub.local` (карточка тренера 1),
  id=5 `both@sporthub.local` (клуб 3 и карточка тренера 2), id=1 `admin@sporthub.local`

⚠️ **Лицо услуг заводит любой вошедший человек (фаза 35, решение 1).** Прав
`manage_own_clubs` и `manage_own_trainer_profile` больше нет — они исчезли вместе с ролями.
Единственная проверка на заведении публикации, помимо входа, — это вид учётной записи:
служебной записи публикации не положены. Ограничение на заведение (модерация, оплата) —
вопрос будущей фазы, и это будет условие на один маршрут, а не новая роль.

## Scenario: Правка и архивирование своего лица

**Role:** id=2 → id=5

- [ ] **step-1** **Дефект 4.6 № 1, закрытый шагом 35.17.** Login id=5 (у него клуб 3
      **и** карточка тренера 2), `PATCH /api/trainers/2` — expect **200**, правка прошла.
      Прежде владелец клуба получал 403 на собственную карточку тренера: право
      `manage_own_trainer_profile` было только у роли `trainer`, а карточка принадлежала
      роли `club_owner`
- [ ] **step-2** `PATCH /api/clubs/3` под той же сессией — 200
- [ ] **step-3** `PATCH /api/trainers/1` (чужая карточка) — expect **403** «Недостаточно
      прав для редактирования тренера с id 1». Assert: карточка не изменилась.
      ⚠️ Запрет остался запретом, сменилась только причина: не «не та роль», а «не твоя вещь»
- [ ] **step-4** `PATCH /api/clubs/1` (чужой клуб) — 403 «Недостаточно прав для
      редактирования клуба с id 1»
      ⚠️ **Шаги 5–8 меняют данные необратимо.** Гнать их последними либо восстанавливать базу:
      `npm run db:reset`, затем `npm run db:migrate --workspace @sporthub/api` и `npm run db:seed`.

- [ ] **step-5** **Решение 21 — архивирование вместо удаления.** Взять клуб 2 «Баланс»
      (владелец id=2, в расписании слот 3), записать на него id=4, затем
      `DELETE /api/clubs/2` под сессией id=2 — expect **409** с текстом

- [ ] **step-6** Отменить запись и повторить `DELETE /api/clubs/2` — expect 200, в ответе

      «Убрано владельцем из каталога»; из публичной выдачи каталога клуб ушёл
- [ ] **step-7** Assert: отзывы, прошлые записи и связи по этому клубу **целы** —
      архивирование прячет лицо, а не стирает чужие слова и чужую историю
- [ ] **step-8** Assert: клуб 2 ушёл из списка публикаций в кабинете, а клуб 1 остался.
      `DELETE /api/trainers/2` (карточка тренера) под сессией id=5 — тем же путём:
      200 и `archived` при отсутствии будущих записей, 409 тем же текстом
      про «карточку» при их наличии
