## Phase 19: Яндекс Карты — живая карта, геокодирование и мульти-город

> После этой фазы: placeholder-карта на главной заменена живой Яндекс Картой с маркерами опубликованных клубов и тренеров. Маркеры фильтруются по режиму поиска (клубы / тренеры), виду спорта и городу. При наведении на маркер — popup с краткой информацией, при клике — переход на деталку. Провайдер при публикации указывает город (select) и адрес (текстовое поле) — координаты определяются через Яндекс Geocoder API и сохраняются в данных сущности. На главной появляется селектор города для фильтрации контента. У пользователей в профиле появляется поле города — залогиненный пользователь видит контент своего города, гость выбирает город из селектора на главной. Архитектура карт модульная и готова к расширению.

Phase 19 — первая фаза с внешним API (Яндекс Карты).
Это MVP-интеграция: карта работает, маркеры отображаются, адрес геокодируется при публикации.
Без Suggest API (геоподсказок на лету), без кластеризации, без мини-карт на деталках, без геолокации пользователя.

**Пререквизит:** перед началом работы у разработчика должен быть API-ключ Яндекс Карт (тип «JavaScript API и HTTP Геокодер»), полученный в кабинете разработчика https://developer.tech.yandex.ru. Ключ указывается в `.env.local` и не коммитится в репозиторий.

### Ключевые решения

**Яндекс Карты:**

- Используем JavaScript API 3.0 — актуальная версия с векторными картами.
- API подключается через CDN (`<Script>` из `next/script`, strategy `lazyOnload`). URL: `https://api-maps.yandex.ru/v3/?apikey={KEY}&lang=ru_RU`. Без npm-пакетов.
- API-ключ хранится в `NEXT_PUBLIC_YANDEX_MAPS_API_KEY` в `.env.local`. Ключ публичный (используется на клиенте), но не коммитится — `.env.local` уже в `.gitignore`. `.env.example` содержит placeholder для будущих разработчиков.
- Геокодирование (адрес → координаты) выполняется через HTTP Geocoder API на серверной стороне (API route) при публикации услуги. Бесплатный лимит — 1 000 запросов/сутки, для MVP более чем достаточно.
- Suggest API (геоподсказки) НЕ подключается в этой фазе — это отдельный платный продукт Яндекса. Вместо подсказок используется проверка адреса через Geocoder по кнопке/сабмиту.

**Одна карта, два набора маркеров:**

- На главной одна карта — не две. Переключатель `discoveryMode` (`clubs` / `trainers`) из `useFilterStore` управляет тем, какие маркеры показываются.
- Маркеры фильтруются по: `discoveryMode` + `selectedSportId` + `selectedCity`.
- Карта центрируется на выбранный город и показывает все маркеры, попадающие в текущие фильтры.
- Зум по умолчанию — отдалённый, чтобы было видно максимум маркеров в городе.

**Координаты — часть данных сущности (уже в модели):**

- Типы `Club` (`coordinates: Coordinates`, required) и `Trainer` (`coordinates?: Coordinates`, optional) уже содержат поле координат. `Offering` тоже имеет `coordinates: Coordinates`.
- Текущие данные содержат заглушку `{ lat: 0, lng: 0 }` — Phase 19 заполнит реальными значениями через Geocoder API.
- Координаты определяются один раз при публикации через Geocoder API и сохраняются в JSON.
- На карте маркеры ставятся по готовым координатам — без runtime-геокодирования.
- Сущности с невалидными координатами (`{lat: 0, lng: 0}`) не отображаются на карте — проверка через хелпер `isValidCoordinates()`.

**Адрес в publish-модалках — два поля:**

- **Город** — select с преднастроенным списком городов. Дефолт — «Самара». Провайдер может выбрать другой город из списка или ввести свой.
- **Адрес** — текстовое поле, куда провайдер пишет улицу и дом (например, «ул. Ленина, 15»).
- При сабмите формы или по кнопке «Проверить адрес» → server-side вызов Geocoder API с запросом `"{город}, {адрес}"` → получение координат + нормализованного адреса → показ провайдеру результата с возможностью подтвердить или исправить.
- Если Geocoder не нашёл адрес — сообщение об ошибке, публикация возможна без координат (маркер просто не появится на карте).

**Мульти-город сразу:**

- Город — это фильтр платформы, аналогичный `sportId` или `searchQuery`.
- В `useFilterStore` добавляется `selectedCity: string` с дефолтом из `DEFAULT_CITY` (Самара).
- На главной появляется селектор города в `SearchControlsPreview`. Хардкоды "Самара" в Header и SearchControlsPreview заменяются на динамику.
- Фильтрация по городу — **client-side** (как discoveryMode и sportId). Сервер отдаёт все данные. Это избегает hydration mismatch.
- Каталог и карта показывают данные только для выбранного города.
- Нормализация города: хелпер `normalizeCity()` приводит любой ввод к каноничному виду ("саМара" → "Самара"). При сравнении — `.toLowerCase()`.

**Город пользователя:**

- В тип `User` добавляется опциональное поле `city?: string`.
- В seed-данных у существующих пользователей `city: 'Самара'`.
- В ЛК спортсмена и провайдера отображается город из профиля (на MVP — без редактирования, просто display; редактирование — позже).
- Если пользователь залогинен и у него есть город → `selectedCity` инициализируется из профиля как дефолт. Селектор города **остаётся видимым** — пользователь может переключить город вручную.
- Если гость (не залогинен) → селектор города видим, дефолт «Самара».

**Маркеры — интерактивность:**

- **Hover (десктоп) / первый тап (мобайл):** popup с мини-информацией — название, вид спорта, адрес, рейтинг.
- **Click / второй тап:** переход на деталку (`/clubs/[slug]` или `/trainers/[slug]`).
- Popup содержит минимум данных — подгрузки из API при hover не делаем, все данные для popup передаются вместе с маркерами.

**Empty state карты:**

- Если для выбранного города и фильтров нет услуг → карта показывает город без маркеров + текстовое уведомление: «В городе {город} пока нет доступных услуг по выбранным фильтрам. Попробуйте изменить фильтры или выбрать другой город.»
- Карта никогда не пустая визуально — всегда показывает хотя бы город.

### Step 19.2: API геокодирования — серверный эндпоинт для определения координат

- **Действие:**
  - создать API route `POST /api/geocode` — принимает `{ city: string, address: string }`, вызывает Яндекс HTTP Geocoder API серверным запросом (`fetch` к `https://geocode-maps.yandex.ru/1.x/`), возвращает `{ success: true, data: { coordinates: { lat, lng }, formattedAddress: string } }` или `{ success: false, error: "..." }`;
  - Geocoder вызывается с параметрами: `geocode="{city}, {address}"`, `format=json`, `results=1`, `apikey` из env;
  - парсинг ответа Яндекса: извлечение координат из `GeoObject.Point.pos` и нормализованного адреса из `GeocoderMetaData.text`;
  - обработка ошибок: невалидный адрес, таймаут API, отсутствие ключа;
  - Zod-схема для валидации входного payload.

- **Проверка:**
  - `POST /api/geocode` с `{ city: "Самара", address: "ул. Ленина, 1" }` возвращает координаты;
  - невалидный адрес возвращает осмысленную ошибку;
  - без API-ключа возвращает ошибку конфигурации.

- **Тесты:**
  - тест на валидацию payload (city обязательный, address обязательный);
  - тест на парсинг ответа Яндекс Geocoder (mock);
  - тест на обработку ошибки от Geocoder (mock);
  - тест на отсутствие API-ключа.

- **Ожидаемый результат:**
  - серверный эндпоинт готов для использования из publish-модалок.

- **Действие:**
