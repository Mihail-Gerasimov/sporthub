> После этой фазы: publish-модалки провайдера валидируют ввод по типу поля (телефон с маской, email, текст без мусора, длительность кратно 5 минутам), город отображается с припиской «г.», длинные описания не ломают layout карточек, баннер impersonation визуально заметен, а нативные select-элементы стилизованы под дизайн проекта.

Phase 18 — фаза правок и полировки. Новых страниц и API не добавляется.
Работа идёт внутри существующих компонентов, схем валидации и стилей.

### Step 18.2: Валидация полей в publish-модалках — телефон, email, текст, длительность

- **Действие:**
  - **Телефон:** добавить маску ввода в поле телефона (`PublishClubModal`). Формат — российский номер. Валидация в клиентском валидаторе (`publish-validation.ts`) и в Zod-схеме (`schemas/publish.ts`).
  - **Email:** проверить валидацию email в обеих модалках. Если в Zod-схеме нет `z.string().email()` — добавить. Убедиться что клиентская и Zod-валидация согласованы.
  - **Текстовые поля — санитизация по типу:**
    - город / имя → только буквы (кириллица, латиница), пробелы, дефисы;
    - адрес → буквы, цифры, точки, запятые, дефисы, пробелы, косая черта;
    - большие текстовые поля (описание, bio) → допускается обычная пунктуация, запрещается мусор (`&^#$@%` и т.п.);
    - числовые поля → только цифры.
  - **Длительность тренировки:** ввод с шагом 5 минут. Если значение не кратно 5 — показать текстовое предупреждение: «Длительность должна быть кратна 5 минутам (например, 55 или 60)». Без автоисправления.
  - Валидацию добавлять и в клиентский валидатор, и в Zod-схему.

- **Проверка:**
  - телефон принимает только корректный номер через маску;
  - email отклоняет невалидный формат;
  - в поле «город» нельзя ввести `"ааадл.(;,.,ШГ2342fsdf"`;
  - длительность 51 показывает предупреждение, 55 и 60 проходят;
  - существующий publish-flow не ломается.

- **Тесты:**
  - тесты валидации телефона (валидный / невалидный формат);
  - тесты валидации email (валидный / невалидный / пустой если optional);
  - тесты санитизации текстовых полей (город, адрес, описание);
  - тесты длительности (кратно 5 / не кратно 5);
  - regression тесты на publish-flow.

### Step 18.3: Display-правки — приписка «г.» к городу и text overflow

- **Действие:**
  - **Город:** при отображении города на публичных карточках и деталках добавить приписку «г.» (display-only). В хранении и формах — чистое значение без приписки. Затрагивает: `ClubCard`, `TrainerCard`, `ClubDetailPageClient`, `TrainerDetailPageClient`, и аналогичные места где рендерится город.
  - **Text overflow на деталках:** добавить `break-words` / `overflow-wrap` к блокам `description`, `bio`, `shortDescription` на страницах `/clubs/[slug]` и `/trainers/[slug]`, чтобы длинный текст без пробелов не вылезал за границы блока.
  - **Line-clamp на превью:** в карточках публикаций ЛК провайдера и в каталожных карточках добавить `line-clamp` + лёгкое затемнение-градиент к длинным описаниям, чтобы текст обрезался аккуратно. На деталке — полный текст без обрезки.

- **Проверка:**
  - город отображается как «г. Самара» на карточках и деталках;
  - в форме редактирования город остаётся «Самара» без приписки;
  - длинный текст без пробелов не ломает layout;
  - на превью длинное описание обрезается с fade, на деталке видно полностью.

- **Тесты:**
  - тест на display-формат города;
  - тест что в хранении город без приписки;
  - visual regression тесты на text overflow.

### Step 18.4: Кастомная стилизация select-элементов

- **Действие:**
  - убрать дефолтные OS/браузерные стили у всех нативных `<select>` в проекте через `appearance-none` + кастомная стрелка (SVG/CSS).
  - Затрагивает:
    - `DashboardPage.tsx` — фильтр роли, фильтр статуса;
    - `PublishTrainerModal.tsx` — выбор вида спорта, привязка к клубу.
  - Стилизация под текущий дизайн: `rounded-card`, `border-line`, `bg-panel`, `text-ink`, focus-ring — как у `Input`.

- **Проверка:**
  - select-элементы выглядят одинаково на macOS, Windows, iOS, Android и в разных браузерах;
  - кастомная стрелка видна и корректно позиционирована;
  - функциональность выбора не нарушена.

- **Тесты:**
  - render тесты на наличие `appearance-none` и кастомной стрелки;
  - regression тесты на работу фильтров и выбора спорта.
