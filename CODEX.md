## Проект

- **Название:** SportHub
- **Назначение:** Маркетплейс спортивных услуг — объединяет клубы, секции, студии и тренеров города в единой экосистеме. Полный цикл: поиск → выбор → запись → оплата → отзыв.
- **Слоган:** Найдите свой спорт. Свой ритм. Свое сообщество.
- **Документация:**
  - `STACK_OVERVIEW.md` — стек, архитектура, соглашения по коду
  - `IMPLEMENTATION_PLAN.md` — пошаговый план реализации MVP: 9 фаз

## Стек

- **Язык:** TypeScript 5.x (строгий режим)
- **Фреймворк:** Next.js 16 (App Router) — монолит: фронт + API в `app/api/`
- **UI:** React 19 + Tailwind CSS 4
- **Стейт:** Zustand
- **БД (MVP):** JSON-файлы (`src/data/`), доступ через абстракцию `src/lib/db.ts`
- **Валидация:** Zod
- **Auth (MVP):** Заглушка — Zustand + localStorage. Позже NextAuth.js
- **Линтер:** ESLint
- **Форматтер:** Prettier
- **Бандлер:** Turbopack (дефолтный в Next.js 16)
- **Рантайм:** Node.js 20 LTS

## Режим работы

**КРИТИЧЕСКИ ВАЖНО — следуй этим правилам ВСЕГДА, без исключений.**

### Работа по плану

- Работаем **СТРОГО** по `IMPLEMENTATION_PLAN.md`, шаг за шагом, по порядку.
- **НЕ** пропускай шаги, **НЕ** меняй порядок, **НЕ** объединяй шаги.
- **НЕ** забегай вперёд. **НЕ** делай шаги из следующих фаз, пока текущая не завершена.
- Перед началом каждого шага: скажи номер шага, название, и что конкретно будешь делать. **Жди подтверждения.**

### Итерации

- За одну итерацию делаем **МАКСИМУМ 1–3 шага**.
- После каждых 1–3 шагов — **ОБЯЗАТЕЛЬНЫЙ СТОП**. Выведи отчёт:
  - Какие шаги выполнены
  - Какие файлы созданы/изменены
  - Какой следующий шаг
- После отчёта — **ЖДИ** команды "ок", "продолжай", "давай дальше" или другого указания. Без команды — не продолжай.

### Совместная работа

- **"помоги"** — дописывай за меня с объяснением что и почему.
- **"проверь"** — ревьюишь код, указываешь на ошибки и как исправить.
- **"объясни"** — объясняй подход и логику перед тем как писать код.

### Код

- Комментарии в коде — на русском.
- Server Components по умолчанию. `"use client"` — только при интерактивности.
- Заглушки помечаем `// STUB:` — чтобы потом легко найти и заменить.
- Все операции с данными — через `lib/db.ts`. Напрямую JSON не читаем.
- API ответы: `{ success: true, data: ... }` или `{ success: false, error: "..." }`.
- Импорты через алиас `@/`.

## Git

### Коммиты

- После **КАЖДОГО** завершённого шага: `git add` + `git commit` с осмысленным сообщением.
- Формат: `тип(модуль): Step X.Y — краткое описание`
- Типы: `feat` (новая функциональность), `fix` (баг), `refactor` (рефакторинг), `chore` (инфраструктура, конфиги), `docs` (документация), `style` (стили/UI)
- Примеры:
  - `chore(infra): Step 1.1 — init project with create-next-app`
  - `feat(types): Step 2.1 — define TypeScript interfaces for all entities`
  - `feat(api): Step 3.2 — clubs API with filters and detail endpoint`
  - `feat(ui): Step 4.2 — base UI components (Button, Card, Modal, Rating)`
  - `feat(page): Step 5.9 — assemble home page with all sections`

### Ветки

- Перед началом **КАЖДОЙ** новой фазы: создай ветку `phase-X` от текущего состояния.
- Работай в ветке фазы. После завершения — пользователь сам решит когда мержить.

### Запреты

- **НЕ** делай `git push` — пользователь сам решит когда пушить.
- **НЕ** делай `git merge` — пользователь сам решит когда мержить.
- **НЕ** делай force push, rebase или другие деструктивные операции.
